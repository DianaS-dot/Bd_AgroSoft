5. PATRÓN DE ARQUITECTURA
================================================================================

Todos los módulos siguen el mismo patrón:

┌─────────────────────────────────────────────────────────────────┐
│                    ARQUITECTURA HEXAGONAL                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  DOMAIN (Core)                                                  │
│  ├── entities/        Entidades de negocio puras                │
│  ├── ports/           Interfaces de repositorio                 │
│  └── exceptions/      Excepciones de dominio                    │
│                                                                 │
│  APPLICATION (Use Cases)                                        │
│  └── use-cases/       Un caso de uso por clase                  │
│                                                                 │
│  INFRASTRUCTURE (Adapters)                                      │
│  ├── database/        Entidades TypeORM (adaptador BD)          │
│  ├── repositories/    Implementación repositorio (PostgreSQL)   │
│  ├── controllers/     Controladores NestJS (REST API)           │
│  ├── dto/             Objetos de transferencia de datos         │
│  └── primary/         Adaptadores primarios (MQTT)              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

Flujo de datos:

  Client HTTP ──▶ Controller ──▶ Use Case ──▶ Repository ──▶ PostgreSQL
      │                             │
      │                             │
      └─── DTO ────────────────────┘
      
  MQTT Broker ──▶ MqttSensorListener ──▶ Use Case ──▶ Repository ──▶ PostgreSQL

================================================================================
